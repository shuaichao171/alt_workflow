# 通用工作守则

## 工具使用

- 如果在任务执行期间打开了软件，应在任务结束时关闭本次任务所打开的软件；不要关闭任务开始前已经运行的软件。
- 找不到本机某个软件或工具的安装路径时，先查阅 [../private/paths.md](../private/paths.md)，不要凭空猜测。

## 缺少工具时

任务需要的工具不存在时，不要停在“未找到”：

1. **先确认真的没有**：查 `private/paths.md`、PATH（`Get-Command <名字>`）、用户提到的目录和 Steam 库。PATH 里没有不代表没装。
2. **一次说清最小方案**：当前产物需要什么能力、候选工具及作者/官方来源、具体版本和平台架构、准备安装到哪里、必需依赖、装完怎么验证。只提当前任务确实需要的，已有工具能完成就复用，不把整套工具链当前置条件。
3. **授权后再装，范围不扩大**：用户同意的工具与依赖可以连续下载、安装、验证，不逐步重复询问；换来源、加系统级依赖或扩大范围要再说明。只说“开发某功能”不等于同意装新软件。账号登录、验证码、许可协议交给用户。
4. **装得干净、可追溯**：只从作者或官方入口下载，记录页面、版本和下载文件的 SHA-256（自己算的哈希只作记录，不冒充官方校验）；免安装包解压到独立的版本目录，不覆盖旧版本，不改全局 PATH，用绝对路径调用。
5. **验证并登记**：用一个最小真实样例跑通（不能只看 `--version`），再把路径登记到 `private/paths.md`；公开文件里只写占位名。

## UI 验证

- 修改 UI 后，应尽可能通过截图或导出图片检查实际效果是否正确。
- 自己无法查看图片时，可调用识图子代理 `vision`（见 [../agents/INDEX.md](../agents/INDEX.md)）。

## 路径

- 工作流内部文件互相引用时使用相对路径，不写绝对路径。
- 本机绝对路径（软件安装位置、游戏目录等）只写在 `private/paths.md`，公开文件里用占位名引用。
