# 04 · 备份与回滚

> 规则：**任何写操作之前先备份**；备份要能说清"备份了什么、放哪、怎么回"。

## 备份什么

| 对象 | 示例路径（相对部署目录） | 说明 |
| --- | --- | --- |
| 状态数据 | `data/accounts.json`、`data/keys.json` | 账号池、下游密钥，丢了要重新登录/重新分发 |
| 运行时配置 | `config/config.json` | 服务器专属配置（监听、上游、池策略） |
| 环境变量 | `.env` | 含管理台密码，600 |
| 上游凭据 | `secrets/*` | AK/SK，600 / 目录 700 |
| compose 定义 | `docker-compose.yml`、`docker-compose.override.yml` | 重装时可对照 |

`app/`（源码副本）不用备份：它随时可由源码目录重建。

## 备份命令

```bash
# 目录约定：<部署目录>/backups/<文件名>.<YYYYmmdd-HHMMSS>.bak
ssh <别名> 'set -e; D=<VPS_<服务>_DEPLOY_DIR>; TS=$(date +%Y%m%d-%H%M%S)
  mkdir -p $D/backups
  for f in data/accounts.json data/keys.json config/config.json; do
    [ -f "$D/$f" ] && cp -p "$D/$f" "$D/backups/$(basename $f).$TS.bak"
  done
  chmod 600 $D/backups/*.$TS.bak
  md5sum $D/backups/*.$TS.bak'

# 或用脚本（会打印同样的路径与 md5）
python scripts/server.py backup --yes --dir <VPS_<服务>_DEPLOY_DIR> \
       --files data/accounts.json data/keys.json config/config.json
```

要点：

- 用 `cp -p` 保留权限/时间；备份文件同样 `chmod 600`（可能含凭据）。
- **把备份路径与 md5 写进交付说明**，否则回滚时找不到"回到哪一份"。
- `.env` 与 `secrets/` 单独 `cp -p` 到 `backups/`，不要 `cat` 到终端。

## 回滚

```bash
# 1) 停服务（避免内存态把回滚的文件覆盖回去）
ssh <别名> 'cd <VPS_<服务>_DEPLOY_DIR> && docker-compose stop'

# 2) 用备份覆盖（先确认备份 md5 与备份时记录一致）
ssh <别名> 'D=<VPS_<服务>_DEPLOY_DIR>; cp -p $D/backups/accounts.json.<TS>.bak $D/data/accounts.json
  chmod 600 $D/data/accounts.json; md5sum $D/data/accounts.json'

# 3) 起服务并验证
ssh <别名> 'cd <VPS_<服务>_DEPLOY_DIR> && docker-compose start'
python scripts/server.py health --port 8787
```

代码回滚见 [02-部署与更新.md](02-部署与更新.md)（重新同步旧版本源码后 `docker-compose restart`）。

## 备份保留

`backups/` 只增不减会占盘（服务器磁盘通常很小，例如 29G / 已用 45%）。
定期清理时按时间戳保留最近 N 份，清理前先确认最新一份能通过回滚演练。
