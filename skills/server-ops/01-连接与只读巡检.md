# 01 · 连接与只读巡检

> 第一次接入一台服务器，或动手前收集事实时读这一页。**本页命令全部只读，可放心跑。**

## 连接方式

1. 目录占位名 → `private/paths.md`「服务器」小节；凭据 → `private/secrets.json` 的 `vps_la`。
2. 推荐在 `~/.ssh/config` 里配别名，之后所有命令只用别名：

```
Host vps-la
    HostName <服务器 IP>
    User root
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
```

3. 首选密钥认证。本机（Windows/MSYS）**没有 `sshpass`**，密码认证无法脚本化；只有密码时请在
   `~/.ssh/config` 配别名并配好密钥，或用交互式 ssh。

```bash
# 连通性（BatchMode 保证不会卡在交互提示上）
ssh -o BatchMode=yes -o ConnectTimeout=10 <别名> 'hostname; uptime'
```

## 基线快照（一台新服务器先看这些）

```bash
ssh <别名> 'cat /etc/os-release | head -2; uname -r; nproc; free -m | head -2; df -h / | tail -1'
ssh <别名> 'docker --version; docker-compose version 2>/dev/null | head -1; docker compose version 2>/dev/null | head -1'
ssh <别名> 'docker ps --format "{{.Names}}|{{.Image}}|{{.Status}}|{{.Ports}}"'
ssh <别名> 'docker network ls --format "{{.Name}}"'
ssh <别名> 'docker images --format "{{.Repository}}:{{.Tag}} {{.Size}}" | head -20'
ssh <别名> 'ls -1 <VPS_DOCKER_ROOT>'          # 同机有哪些 docker 项目
ssh <别名> 'for t in jq curl tar gzip rsync python3 node nodejs; do printf "%-8s %s\n" "$t" "$(command -v $t || echo MISSING)"; done'
```

要点：**宿主机可能没有 node**（服务跑在容器里）。要解析 `data/*.json` 时用 `python3 -c`，
不要在宿主机上装 node；容器内才有 node（`docker exec <容器> node -e …`）。

## 容器级事实

```bash
# 挂载关系（判断哪些是宿主机目录、哪些是卷，改数据前必看）
ssh <别名> 'docker inspect <容器> --format "{{range .Mounts}}{{.Source}} -> {{.Destination}} ({{.Mode}}){{println}}{{end}}"'

# 健康状态 / 重启策略
ssh <别名> 'docker inspect -f "{{.State.Health.Status}} restart={{.HostConfig.RestartPolicy.Name}} image={{.Config.Image}}" <容器>'

# 端口绑定（只绑 127.0.0.1 = 对外走 Nginx 反代）
ssh <别名> 'docker ps --format "{{.Names}} {{.Ports}}"'
```

## 服务自检

```bash
# 应用健康检查（容器内端口通常只绑本机回环，从服务器上 curl）
ssh <别名> 'curl -s -m 5 http://127.0.0.1:8787/health'
ssh <别名> 'docker exec <容器> node src/cli.js doctor'      # 项目自带的自检
```

## 日志与资源

```bash
ssh <别名> 'docker logs --since 10m <容器> 2>&1 | tail -50'
ssh <别名> 'docker logs --since 5m <容器> 2>&1 | grep -ciE "error|fail|refused"'   # 新错误计数
ssh <别名> 'docker stats --no-stream --format "{{.Name}} {{.CPUPerc}} {{.MemUsage}}"'
ssh <别名> 'df -h /; free -m | head -2'
```

## 一键巡检

```bash
python scripts/server.py doctor      # 本机依赖 + 连通性 + 服务器基线 + 容器/端口/磁盘
```

`doctor` 输出是判断「现在能不能动」的依据：磁盘满、容器 unhealthy、依赖服务不在，
都应当先修好再做变更。
