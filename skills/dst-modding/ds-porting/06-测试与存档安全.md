# 06 测试与存档安全

单机版没有专用服务器，联机版的无头测试（[dst-dedicated-server-testing](../mod-skills/dst-dedicated-server-testing/SKILL.md)）不适用。单机用「静态检查 + 游戏内自动测试模组」验证。

**启动游戏、启用测试模组、生成或删除存档之前，完整读完本文第 3 节。** 启动游戏会写真实存档数据，属于需要先备份的操作。

## 1. 静态检查（每次改动后）

| 检查 | 做法 |
|---|---|
| Lua 5.1 语法 | `../mod-skills/dst-debugging-testing/scripts/dst_lua_check.py <模组目录> --source-dir DS_GAME_DIR\data\DLC0003\scripts`：lupa 的 Lua 5.1 编译加组件方法声明核对。核对单机 API 时 `--source-dir` 必须指向单机源码（按目标 DLC 换 `data\scripts` 或 `DLC000x\scripts`），不能用默认的联机版 scripts.zip。也可用各模组的 `_ai_work/verify.py`（沃尔特、旺达）或 `luac -p`。字符串表少一个引号就会加载即崩（沃尔夫冈） |
| 音效路径 | 解析 FEV 得到事件列表，比对代码里的全部路径（见 [04](04-音效移植.md) 第 5 节） |
| 资源存在性 | 代码引用的 anim / images / 动画名在实际 zip 里存在 |
| LuaLS | error 级别诊断，配置 Lua 5.1，不要靠关掉未定义全局来"通过" |
| 离线模拟 | 逻辑分支多的机制可用 lupa 加载组件做离线断言（沃尔夫冈 `artifacts/check_mighty_equip_slow.py` 模拟两条移速通道） |

静态检查只能证明能加载，不能证明 tick 行为、动画、声音、存档正确。报告里写「仅通过静态检查，未实机」。

## 2. 游戏内自动测试模组

参考实现：沃尔特（`git show HEAD:_ai_work/autotest/...`）、旺达和温蒂的 `_ai_work/autotest/`。

### 结构

- 临时模组 `<模组>_autotest`，`modsettings.lua` 里加 `ForceEnableMod("<模组>")` 和 `ForceEnableMod("<模组>_autotest")`（参数是文件夹名，不是显示名）。
- **每次读世界 Lua 都会完全重置**，所以用 `TheSim:SetPersistentString` / `GetPersistentString` 保存一个 JSON 状态机，阶段如：`start_rog → rog → rog_reload → start_sw → sw → start_ham → ham → cleanup → done`。
- 每次运行换一个新的 `RUN_ID`：状态文件里不是本次 `RUN_ID` 的旧状态一律不续跑（Steam 云会把删掉的文件重新下载回来）。
- 使用专门的测试存档位（9 或 10），**开始前确认为空**；状态文件不属于测试框架而存档位有内容时，直接 FAIL 并拒绝操作。
- 前端：钩 `screens/mainscreen`，稳定约 2 秒后读状态决定下一步。新世界用：

  ```lua
  SaveGameIndex:StartSurvivalMode(slot, "<角色>", { ROGEnabled = dlc.REIGN_OF_GIANTS },
      function() StartNextInstance({ reset_action = RESET_ACTION.LOAD_SLOT, save_slot = slot }) end,
      dlc, mode)   -- mode: "survival" / "shipwrecked" / "porkland"
  ```

- 世界内：`AddSimPostInit` 读状态，执行本阶段用例；存档重载阶段用 `SaveGameIndex:SaveCurrent` 后重新加载同一存档位。
- 旺达的变体：先建 RoG 世界，再在**同一存档位**内按航海门的方式依次并入海难和哈姆雷特，用来测跨世界功能。
- 日志统一前缀：`[<模组>_AUTOTEST] PASS / FAIL / INFO <说明>`，结束打印 `ALL DONE`。
- 收尾：`SaveGameIndex:DeleteSlot` → 恢复原来的 DLC 启用状态 → `EraseFiles(cb, { 状态文件, "survival_<slot>", "shipwrecked_<slot>", "porkland_<slot>" })` → `RequestShutdown()`。**测试文件只能在游戏内删除**：游戏关闭时手动删云存档文件，Steam 下次启动会重新下载回来。

### 用例怎么写

- 走玩家真实路径：真实右键动作、BufferedAction、SG、Brain、投射物，不要直接改组件字段冒充成功。旺达的测试改成走真实右键路径后才发现右键施法不可用。
- 等真实 tick：冷却、投射物飞行、Brain 下一轮都要留时间，不要在同一帧断言内部字段。
- 重载阶段的首个断言前留一个预热步（≥0.5 s）：技能树的效果重放是 `DoTaskInTime(0)` 的 sim 任务，而 `AddSimPostInit` 后同步跑的首个用例会在世界第一帧**之前**执行，直接断言标签/配方会看到“恢复失败”的假象（沃姆伍德 2026-10-31，诊断打 `effects_applied/_restoring/_applytask` 即可分辨）。
- 技能树断言的技能预算：点数上限就是阈值总数（15 点），跨分支组合断言前先数一遍根技能+前置链+门槛（≥5 分支标签、12 点门槛）是否装得下，装不下就拆成两个用例（沃姆伍德 run3 教训：17 点装不进 15 点预算，忠诚锁死级联 8 个假 FAIL）。
- 正反对照：技能学了生效 / 没学不生效；供电工作 / 断电停止；互斥技能不能同时取得。
- 避免测试污染：例如测炮塔索敌不要让玩家自己设目标（玩家会出拳造成假伤害）；被测目标停掉 Brain 固定位置。
- 覆盖存档重载、跨世界、船上、室内、死亡复活、受击打断等边界。
- 每个修过的 bug 补一条回归断言。

已有规模参考：旺达 324 项、温蒂 303 项、沃尔特（RoG 60 项 + SW + Hamlet）均在 RoG → 重载 → SW → Hamlet 全部通过。

### 自动测试覆盖不到的

人耳试听、手柄操作、视觉效果（贴图、特效朝向、动画观感）。纯本体（不开 RoG）世界在哈姆雷特合并安装下无法通过存档接口生成（原版世界生成报错，与模组无关）。这些项在报告里明确写「未覆盖」。

## 3. 存档安全（启动游戏前必做）

1. **确认没有正在运行的 `dontstarve_steam` 进程**。若用户已开着游戏，停下来等用户自己关，不操作也不结束它。
2. **完整备份 Steam 云存档目录** `DS_STEAM_CLOUD_DIR`（`<Steam>\userdata\<账号>\219740`，含 `remote/` 和 `remotecache.vdf`），以及 `DS_GAME_DIR\mods\modsettings.lua`。每轮用新的时间戳目录，记录每个文件的相对路径、大小、SHA-256。哈希只能发现变化，不能代替备份。
3. 有多个 Steam 账号目录时，按最近修改时间和 `remotecache.vdf` 确认当前账号，不要默认取第一个。
4. 只临时追加 `ForceEnableMod`，不改其他模组的启用状态，不用游戏内菜单重写整个设置文件。
5. **不要在测试中途切换 DLC 组合**：只开 RoG 时，其他已安装模组会因缺少海难资源报错。确需切换时，必须先回到前端完整卸载资源（`Load FE: done`）后再启用目标 DLC，否则地图生成后触发原生断言 `mMaskTexture != INVALID_RESOURCE_HANDLE`。
6. 结束后（无论通过与否）：只停止本次启动的游戏进程 → 恢复 `modsettings.lua` → 恢复 `modindex`、`profile`、`saveindex`、`morgue` 等为备份 → 比较文件集合和哈希差异为 0 → 删除临时测试模组。
7. 最后只启用正式模组做一次**干净前端启动**：日志出现 `LOADING LUA SUCCESS`、`Load FE: done`，没有模组 Lua、动画、FMOD 错误；再恢复一次设置并核对。

完整 PowerShell 命令、进程监控、DLC 切换细节见 `DS_PORT_KIT_DIR\references\runtime-testing.md`。

## 4. 启动与日志

- 从 `DS_GAME_DIR\bin` 启动 `dontstarve_steam.exe`。`Start-Process` 返回的 PID 可能只是短命父进程，按进程名跟踪；不要因父进程退出就再开第二个实例。
- 每 30–50 秒读一次 `DS_LOG`；海难、哈姆雷特世界生成明显更慢。
- 关注：测试前缀结果、`LUA ERROR`、`stack traceback`、`attempt to`、`Assert failure`、`Could not find anim`、与模组工程名相关的 `FMOD Error`、`SpawnPrefab returned nil`（往前找该 prefab 构造的第一条错误）。
- 按来源归因：堆栈进入 `mods/<模组>/` 就是模组缺陷；纯本体噪声（缺 `ragtime` 事件等）只有确认与模组调用无关时才可忽略。
- 修复后重跑所有受影响的世界，不只复测出错的那个 DLC。
- HUD 问题可在测试 mod 里加探针：打印控件 `GetWorldPosition()`、相邻徽章距离换算的缩放、`TheSim:GetScreenSize()`，断言控件包围盒在屏幕内且不与徽章重叠；截图用 `PrintWindow`（flag 3）只截游戏窗口，进程须先 `SetProcessDPIAware`，否则高 DPI 下只截到左上一部分。
- 只在某一世界出现、换世界同步骤通过的失败：先加状态轨迹（逐帧记录 `sg.currentstate` 变化）和真实输入检测（钩子里记录非模拟的 `IsControlPressed` 为真）再重跑，未复现的如实写“未复现、原因未定”，不要直接判定为环境噪声。
- 天气会改变角色状态：SW 雨天让 WX-78 每 5 次潮湿判定掉 1 格电，长测试中途芯片断电，后续步骤全错。测试 mod 里按秒补满会被天气消耗的资源（电量、潮湿度），只在刻意测试掉电的步骤关掉，并打印每次补充以便追查。
- 测试运行中改模组代码：下一个世界加载时会读到新代码，结果混杂新旧代码；改完应在新一轮（换 `RUN_ID`）完整重跑。
- 逐帧采样的状态轨迹会漏掉同一帧内进入又离开的状态（例如松手进入 `wx_spin_stop`、同帧被移动打断进 `run_start`），据此判 FAIL 是假失败。要断言状态转换顺序时，在测试 mod 里包装 `player.sg.GoToState` 记录每次转换（wx78 run4 教训）。
- 截图/读日志脚本的三个坑：(1) 游戏运行时 `log.txt` 被独占写入，`[IO.File]::ReadAllText` 会失败，要用 `File.Open(..., 'Read', 'ReadWrite')` 共享读取；(2) 日志路径含中文（`D:\文档\...`）时，无 BOM 的 .ps1 在 Windows PowerShell 5 下按 GBK 解析，路径乱码，脚本静默空转，应改用 pwsh 或存为 UTF-8 BOM；(3) 监视脚本在游戏启动前就会读到上一轮日志里残留的 `HUD_SHOT_*` 标记，必须等日志修改时间晚于本次启动再开始匹配。
- 同一模组同一时间只能有一个会话跑游戏内测试。启动前检查是否有其他会话在改同一模组或使用 `mods/<模组>_autotest`；测试 mod 源码（`_ai_work/autotest`）开跑前先备份，另一会话可能整份覆盖 `modmain.lua`。日志里出现别的测试前缀、`ALL DONE` 时间异常早，就说明本轮结果被别的会话覆盖：不能采信，备份并换 `RUN_ID` 重跑。存档还原以本任务**第一次**启动前的备份为准，别的会话事后做的“基线”可能已含测试改动（wx78 2026-11-06：另一会话把 `ForceEnableMod` 测试行当成了基线）。

## 5. 单机测试可选静音（Windows）

### 何时启用

- 测试驱动可提供 `-MuteGame` 开关；默认不改声音。用户要求静音，或本次测试配置明确启用时使用，不必每轮重复确认。
- 常规行为回归可以静音；人耳试听、音量/循环音观感验收保留声音。静音运行仍可查 FMOD 错误和音效 API 行为，但不能报告“已试听”。
- 使用 Windows **音频会话**的静音开关，只处理本轮启动的 `dontstarve_steam.exe`。不改系统总音量、其他程序、联机版，也不写游戏的音量配置。无需管理员权限或安装额外软件。

### 接入测试驱动

辅助脚本：[ds_test_audio.ps1](../scripts/ds_test_audio.ps1)，原生接口定义：[ds_test_audio.cs](../scripts/ds_test_audio.cs)。在 Windows PowerShell 5.1 或 PowerShell 7 中点入脚本；加载脚本、创建状态和查询会话都不会静音，只有 `Update-DsTestAudioMute` 执行写入。

1. 按第 3 节完成进程检查和存档备份。开启静音时，在启动游戏**之前**记录 UTC 时间，创建新的音频状态文件，放在目标模组本轮 `_ai_work/` 目录。文件包含原静音状态和会话标识，不入库；已有文件不能覆盖。
2. 在现有日志/进程监控循环内调用 `Update-DsTestAudioMute`。它核对完整可执行文件路径和启动时间，排除之前已运行的游戏；枚举所有活跃播放设备，处理一个进程的全部独立会话。Steam 替换启动 PID 或游戏重启后继续轮询，保留本轮第一份恢复基线，避免把继承的临时静音误记为用户原状态。
3. 游戏尚未创建音频会话时，返回 `MatchedSessions = 0`，继续有界等待，不要报告静音成功。确认 `MatchedSessions > 0` 且等于 `ConfirmedMuted` 后记录“静音已确认”；超时则明确报告静音未确认，并按本次测试要求决定是否停止。
4. 把 `Restore-DsTestAudioMute` 放进 `finally`，在游戏退出或强制停止**之前**执行。原来有声则恢复有声，原来静音则仍保持静音；音量数值不变。然后继续第 3 节的停止进程、存档还原与临时模组清理。
5. 会话已消失、设备断开或 API 报错时，保留状态文件并报告未恢复项目，不能声称清理完成。驱动异常退出后可用 `Read-DsTestAudioState` 读取原记录重试；必要时在下一次获准启动该单机程序时完成恢复。不要改系统总音量来兜底。
6. 交给用户手动测试时保留状态文件及游戏，明确静音是否开启；用户测试结束后再恢复与清理，不在交接时自动关游戏。若需要恢复声音，尽量在用户退出游戏前执行。

下面是接入已有驱动的片段。`$workflowRoot`、`$gameDir` 从私有路径配置取得；`$workDir` 是本轮测试目录。原有的存档备份、启动、监控和退出逻辑仍按第 3、4 节执行。

```powershell
param([switch]$MuteGame)
. (Join-Path $workflowRoot 'skills/dst-modding/scripts/ds_test_audio.ps1')
$startedUtc = [datetime]::UtcNow
$audio = $null
if ($MuteGame) {
    $audio = New-DsTestAudioState `
        -GameExecutable (Join-Path $gameDir 'bin/dontstarve_steam.exe') `
        -StartedAfterUtc $startedUtc `
        -StatePath (Join-Path $workDir 'audio-state.json')
}
try {
    # 在这里接原有启动逻辑；下面这段放到其每轮监控中。
    if ($null -ne $audio) {
        $audioStatus = Update-DsTestAudioMute -State $audio
        # 仅在 MatchedSessions > 0 且全部确认时记录静音成功。
    }
} finally {
    try {
        if ($null -ne $audio) {
            $restored = Restore-DsTestAudioMute -State $audio
            if (-not $restored.Complete) {
                Write-Warning "Audio restore pending: $($restored.Pending); keep audio-state.json"
            }
        }
    } finally {
        # 先恢复音频，再执行原有的进程/存档清理。
    }
}
```

不要用 `Profile:SetVolume(0, 0, 0)` 代替临时静音：它会保存设置。原版 `TheMixer:PushMix("mute")` 也不是完全静音，仍保留界面声和部分环境声。这里采用系统会话静音，覆盖该进程全部游戏与模组声音。

接口依据：[按进程识别音频会话](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessioncontrol2-getprocessid)、[设置会话静音](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-isimpleaudiovolume-setmute)。2026-11-17 验证：只读识别到真实单机音频会话；原生静音/读回/恢复在独立的零信号音频进程上通过，未修改正在手动测试的游戏声音。设备拔插及真实游戏跨 PID 重启未实机覆盖。

维护脚本时，运行 `../tests/test_ds_test_audio.ps1 -WorkDir <测试工作目录>` 检查进程隔离、原状态保存、重启继承、恢复失败与重试；另用 **pwsh** 运行 `../tests/test_ds_test_audio_native.ps1 -WorkDir <测试工作目录>`，在独立的静音音频进程上验原生接口，不拿用户正在玩的游戏做静音探针。
