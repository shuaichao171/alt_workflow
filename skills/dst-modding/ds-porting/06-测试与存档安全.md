# 06 测试与存档安全

单机版没有专用服务器，联机版的无头测试（[dst-dedicated-server-testing](../mod-skills/dst-dedicated-server-testing/SKILL.md)）不适用。单机用「静态检查 + 游戏内自动测试模组」验证。

**启动游戏、启用测试模组、生成或删除存档之前，完整读完本文第 3 节。** 启动游戏会写真实存档数据，属于需要先备份的操作。

## 1. 静态检查（每次改动后）

| 检查 | 做法 |
|---|---|
| Lua 5.1 语法 | `../mod-skills/dst-debugging-testing/scripts/dst_lua_check.py <模组目录> --source-dir DS_GAME_DIR\data\DLC0003\scripts`：lupa 的 Lua 5.1 编译加组件方法声明核对。核对单机 API 时 `--source-dir` 必须指向单机源码（按目标 DLC 换 `data\scripts` 或 `DLC000x\scripts`），不能用默认的联机版 scripts.zip。也可用各模组的 `_ai_work/verify.py`（沃尔特、旺达）或 `luac -p`。字符串表少一个引号就会加载即崩（沃尔夫冈） |
| 音效路径 | 解析 FEV 得到事件列表，比对代码里的全部路径（见 [04](04-音效移植.md) 第 5 节） |
| 资源存在性 | 代码引用的 anim / images / 动画名在实际 zip 里存在 |
| LuaLS | error 级别诊断，配置 Lua 5.1，不要靠关掉未定义全局来"通过" |
| 离线模拟 | 逻辑分支多的机制可用 lupa 加载组件做离线断言（沃尔夫冈 `artifacts/check_mighty_equip_slow.py` 模拟两条移速通道） |

静态检查只能证明能加载，不能证明 tick 行为、动画、声音、存档正确。报告里写「仅通过静态检查，未实机」。

## 2. 游戏内自动测试模组

参考实现：沃尔特（`git show HEAD:_ai_work/autotest/...`）、旺达和温蒂的 `_ai_work/autotest/`。

### 结构

- 临时模组 `<模组>_autotest`，`modsettings.lua` 里加 `ForceEnableMod("<模组>")` 和 `ForceEnableMod("<模组>_autotest")`（参数是文件夹名，不是显示名）。
- **每次读世界 Lua 都会完全重置**，所以用 `TheSim:SetPersistentString` / `GetPersistentString` 保存一个 JSON 状态机，阶段如：`start_rog → rog → rog_reload → start_sw → sw → start_ham → ham → cleanup → done`。
- 每次运行换一个新的 `RUN_ID`：状态文件里不是本次 `RUN_ID` 的旧状态一律不续跑（Steam 云会把删掉的文件重新下载回来）。
- 使用专门的测试存档位（9 或 10），**开始前确认为空**；状态文件不属于测试框架而存档位有内容时，直接 FAIL 并拒绝操作。
- 前端：钩 `screens/mainscreen`，稳定约 2 秒后读状态决定下一步。新世界用：

  ```lua
  SaveGameIndex:StartSurvivalMode(slot, "<角色>", { ROGEnabled = dlc.REIGN_OF_GIANTS },
      function() StartNextInstance({ reset_action = RESET_ACTION.LOAD_SLOT, save_slot = slot }) end,
      dlc, mode)   -- mode: "survival" / "shipwrecked" / "porkland"
  ```

- 世界内：`AddSimPostInit` 读状态，执行本阶段用例；存档重载阶段用 `SaveGameIndex:SaveCurrent` 后重新加载同一存档位。
- 旺达的变体：先建 RoG 世界，再在**同一存档位**内按航海门的方式依次并入海难和哈姆雷特，用来测跨世界功能。
- 日志统一前缀：`[<模组>_AUTOTEST] PASS / FAIL / INFO <说明>`，结束打印 `ALL DONE`。
- 收尾：`SaveGameIndex:DeleteSlot` → 恢复原来的 DLC 启用状态 → `EraseFiles(cb, { 状态文件, "survival_<slot>", "shipwrecked_<slot>", "porkland_<slot>" })` → `RequestShutdown()`。**测试文件只能在游戏内删除**：游戏关闭时手动删云存档文件，Steam 下次启动会重新下载回来。

### 用例怎么写

- 走玩家真实路径：真实右键动作、BufferedAction、SG、Brain、投射物，不要直接改组件字段冒充成功。旺达的测试改成走真实右键路径后才发现右键施法不可用。
- 等真实 tick：冷却、投射物飞行、Brain 下一轮都要留时间，不要在同一帧断言内部字段。
- 重载阶段的首个断言前留一个预热步（≥0.5 s）：技能树的效果重放是 `DoTaskInTime(0)` 的 sim 任务，而 `AddSimPostInit` 后同步跑的首个用例会在世界第一帧**之前**执行，直接断言标签/配方会看到“恢复失败”的假象（沃姆伍德 2026-10-31，诊断打 `effects_applied/_restoring/_applytask` 即可分辨）。
- 技能树断言的技能预算：点数上限就是阈值总数（15 点），跨分支组合断言前先数一遍根技能+前置链+门槛（≥5 分支标签、12 点门槛）是否装得下，装不下就拆成两个用例（沃姆伍德 run3 教训：17 点装不进 15 点预算，忠诚锁死级联 8 个假 FAIL）。
- 正反对照：技能学了生效 / 没学不生效；供电工作 / 断电停止；互斥技能不能同时取得。
- 避免测试污染：例如测炮塔索敌不要让玩家自己设目标（玩家会出拳造成假伤害）；被测目标停掉 Brain 固定位置。
- 覆盖存档重载、跨世界、船上、室内、死亡复活、受击打断等边界。
- 每个修过的 bug 补一条回归断言。

已有规模参考：旺达 324 项、温蒂 303 项、沃尔特（RoG 60 项 + SW + Hamlet）均在 RoG → 重载 → SW → Hamlet 全部通过。

### 自动测试覆盖不到的

人耳试听、手柄操作、视觉效果（贴图、特效朝向、动画观感）。纯本体（不开 RoG）世界在哈姆雷特合并安装下无法通过存档接口生成（原版世界生成报错，与模组无关）。这些项在报告里明确写「未覆盖」。

## 3. 存档安全（启动游戏前必做）

1. **确认没有正在运行的 `dontstarve_steam` 进程**。若用户已开着游戏，停下来等用户自己关，不操作也不结束它。
2. **完整备份 Steam 云存档目录** `DS_STEAM_CLOUD_DIR`（`<Steam>\userdata\<账号>\219740`，含 `remote/` 和 `remotecache.vdf`），以及 `DS_GAME_DIR\mods\modsettings.lua`。每轮用新的时间戳目录，记录每个文件的相对路径、大小、SHA-256。哈希只能发现变化，不能代替备份。
3. 有多个 Steam 账号目录时，按最近修改时间和 `remotecache.vdf` 确认当前账号，不要默认取第一个。
4. 只临时追加 `ForceEnableMod`，不改其他模组的启用状态，不用游戏内菜单重写整个设置文件。
5. **不要在测试中途切换 DLC 组合**：只开 RoG 时，其他已安装模组会因缺少海难资源报错。确需切换时，必须先回到前端完整卸载资源（`Load FE: done`）后再启用目标 DLC，否则地图生成后触发原生断言 `mMaskTexture != INVALID_RESOURCE_HANDLE`。
6. 结束后（无论通过与否）：只停止本次启动的游戏进程 → 恢复 `modsettings.lua` → 恢复 `modindex`、`profile`、`saveindex`、`morgue` 等为备份 → 比较文件集合和哈希差异为 0 → 删除临时测试模组。
7. 最后只启用正式模组做一次**干净前端启动**：日志出现 `LOADING LUA SUCCESS`、`Load FE: done`，没有模组 Lua、动画、FMOD 错误；再恢复一次设置并核对。

完整 PowerShell 命令、进程监控、DLC 切换细节见 `DS_PORT_KIT_DIR\references\runtime-testing.md`。

## 4. 启动与日志

- 从 `DS_GAME_DIR\bin` 启动 `dontstarve_steam.exe`。`Start-Process` 返回的 PID 可能只是短命父进程，按进程名跟踪；不要因父进程退出就再开第二个实例。
- 每 30–50 秒读一次 `DS_LOG`；海难、哈姆雷特世界生成明显更慢。
- 关注：测试前缀结果、`LUA ERROR`、`stack traceback`、`attempt to`、`Assert failure`、`Could not find anim`、与模组工程名相关的 `FMOD Error`、`SpawnPrefab returned nil`（往前找该 prefab 构造的第一条错误）。
- 按来源归因：堆栈进入 `mods/<模组>/` 就是模组缺陷；纯本体噪声（缺 `ragtime` 事件等）只有确认与模组调用无关时才可忽略。
- 修复后重跑所有受影响的世界，不只复测出错的那个 DLC。
