# 01 流程与模组结构

## 1. 原则

1. **先删网络，再补本地**：`player_classified`、`net_*`、Replica、RPC、`TheNet`、`ismastersim` 全部去掉，改为本地组件字段、本地事件和本地 HUD。
2. **对照官方实现，不凭印象重写**：每个机制先读联机版原文件，再在单机四份源码里找对应 API。联机版的过滤条件、边界检查往往是机制正确的关键（例：沃比拾取漏了联机版的过滤，导致沃尔特捡不到东西）。
3. **只移植会用到的常量**：不要整份复制 `tuning.lua`，只写本模组读取的 `TUNING`。
4. **按签名探测 DLC，不按常量猜**：常量存在不代表函数签名也是新版（见 [03](03-技能树配方与界面.md) 的 Recipe 探测）。
5. **兼容分层**：哈姆雷特完整实现，Base / RoG / SW 用存在性检查、空实现或替代路径兜底，保证不出现 nil 崩溃。
6. **不能 1:1 时用单机已有系统映射**，并在代码注释和 README「与联机版的差异」表里写清原因。
7. **钩子要幂等、要包装不要替换**：每个 PostInit / 类方法钩子带 `_<模组>_<功能>_hook` 标志；修改动作处理器、SG 事件时包装原函数，未命中的分支照常调用原逻辑，避免覆盖其他模组的修改。
8. **资源只注册一次**：`SOUNDPACKAGE` / `SOUND` 只在 `modmain` 的 `Assets` 里注册，重复注册会导致 FMOD 硬崩溃。

## 2. 两种角色策略

| 策略 | 适用 | 做法 | 案例 |
|---|---|---|---|
| 扩展既有角色 | 单机已有该角色（伍迪、沃尔夫冈、威尔逊、薇洛、薇格弗德、沃姆伍德、机器人、麦斯威尔、温蒂） | `AddPrefabPostInit("<角色>")`，或在 `scripts/prefabs/` 放同名文件覆盖 | woodie、wx78、waxwell |
| 注册新角色 | 单机没有该角色（沃托克斯、沃特、薇诺娜、旺达、沃尔特） | `AddModCharacter` + `scripts/prefabs/<角色>.lua` + 肖像、地图图标、选人台词 | wortox、walter、wanda |

先确认单机四个版本里是否真的有该角色：沃姆伍德只在哈姆雷特里有，Base/RoG/SW 只需保证加载不崩。

另外检查创意工坊里是否已有同名 prefab 的模组（如旺达），在 README 的兼容性一节写明不能同时启用。

## 3. 目录骨架

```text
<角色>/
├── modinfo.lua              # 四 DLC 兼容、api_version = 6、priority、配置项
├── modmain.lua              # 入口：环境、Assets、PrefabFiles、modimport 顺序
├── modicon.png/.tex/.xml    # 256×256
├── main/                    # modimport 加载的逻辑
│   ├── assets.lua           # 图集、物品栏图标注册
│   ├── sounds.lua           # 音效路径表 + RemapSoundEvent
│   ├── string_zh.lua / string_en.lua
│   ├── tuning.lua           # 读取 GetModConfigData
│   ├── dst_tuning.lua       # 本模组用到的联机版数值
│   ├── recipe.lua           # 建造权限检查等配方钩子
│   ├── hook.lua             # 组件、动作、SG 补丁
│   ├── register_character.lua（新角色）/ <角色>_character.lua（扩展）
│   └── skilltree_hud.lua    # 技能树入口按钮 + 暂停菜单项
├── scripts/
│   ├── components/<角色>_skills.lua            # 技能静态定义
│   ├── components/<角色>_skilltreeupdater.lua  # XP、加点、存档
│   ├── <角色>_recipes.lua    # 角色配方（出生时注册）
│   ├── prefabs/ screens/ widgets/ stategraphs/ brains/
├── anim/ images/ bigportraits/ sound/
├── README.md                # 内容、与联机版的差异、兼容性、回归清单
└── _ai_work/                # 工作脚本、测试模组、备份（发布时排除）
```

### scripts/ 命名冲突（重要）

所有模组的 `scripts/` 共用同一个 `require` 命名空间，同路径文件只有一个生效。

- 本模组独有的文件加角色前缀：`walter_skills.lua`、`wanda_strings_data.lua`。
- 不要发布通用名的垫片文件（如 `scripts/dst_functions.lua`）：旺达移植曾因此和其他移植模组互相覆盖，最后删掉了没用到的那份。
- 必须用通用名的组件（如 `components/rechargeable.lua`）要实现**与联机版完全相同的 API**，让任何一个模组的副本生效都能工作；附加 UI（冷却环）在添加前先检查是否已被别的模组加过。

## 4. modinfo / modmain 要点

```lua
-- modinfo.lua
api_version = 6
priority = -10001            -- 低于 Insight 等常用模组（约 -10000）
dont_starve_compatible = true
reign_of_giants_compatible = true
shipwrecked_compatible = true
hamlet_compatible = true
dst_compatible = false
-- 中文检测：locale == "zh" or locale == "zhr"
```

```lua
-- modmain.lua
GLOBAL.setmetatable(env, { __index = function(_, k) return GLOBAL.rawget(GLOBAL, k) end })
TUNING.DST_<角色>_MOD_ZN = GetModConfigData("language") == "zn"
PrefabFiles = { ... }
Assets = { ..., Asset("SOUNDPACKAGE", "sound/<工程>.fev"), Asset("SOUND", "sound/<工程>.fsb") }
modimport("main/sounds.lua")
modimport(TUNING.DST_<角色>_MOD_ZN and "main/string_zh.lua" or "main/string_en.lua")
modimport("main/tuning.lua") ; modimport("main/dst_tuning.lua")
modimport("main/recipe.lua") ; modimport("main/hook.lua")
modimport("main/register_character.lua") ; modimport("main/skilltree_hud.lua")
```

- `modimport` 环境里的普通赋值，之后被 `require` 加载的 prefab、widget、SG 不一定看得见。跨文件共享的表显式写 `GLOBAL.<名字> = ...`，否则延迟加载的 SG 首次进入某状态时触发 `strict.lua` 未声明全局崩溃。
- 旧版单机会在 `Settings` 完整解码前加载 `modmain.lua`：依赖设置的判断放进回调里动态读取，不要在文件顶层缓存。
- 字符串优先用联机版官方中英文（`chinese_s.po`、`speech_<角色>.lua`），台词跟随游戏语言，可在配置项改。

## 5. 阶段清单

### A 调研

1. 列出联机版目标：prefab、组件、技能树文件（`skilltree_<角色>.lua`）、专属物品、SG 状态、Brain、音效工程名。
2. 在单机四份源码里逐个搜索同名组件和 API，记录「联机版调用 → 单机对照 → 移植做法」。
3. 决定角色策略（扩展或新增）。
4. 列出无法移植的内容和替代方案：平面伤害、Boss 门槛、鬼魂、分片、指令轮盘、VFX 粒子等（见 [02](02-API差异速查.md) 第 4 节）。

### B 资源

导出动画、贴图、肖像、技能树 UI、音效（见 [04](04-音效移植.md)、[05](05-资源与发布.md)）。用实际 bank 里的动画名核对 `PlayAnimation`，文件存在不代表联机版的动画名存在。

### C 骨架

modinfo、modmain、角色注册或 PostInit、空技能树 updater 与存档、每日经验。

### D 玩法

技能定义（坐标抄联机版）→ `onactivate` → 专属 prefab → SG / Action / Brain / hook → 阵营、死亡、船上、室内、跨世界边界。

### E 界面

技能树 Screen、左上角按钮、暂停菜单项、专属徽章、冷却环、角色制作栏。

### F 验证

静态检查 → 游戏内自动测试四个世界 → 删除测试代码后干净启动（见 [06](06-测试与存档安全.md)）。

## 6. 新角色最小切片顺序

1. 能选人进档、说话、基础三维
2. 技能树空壳 + 存档
3. 第一条纯数值技能
4. 第一个专属物品配方
5. 核心机制（魂、变身、跳跃、年龄……）
6. 音效与特效
7. 全部技能、互斥、锁
8. 四 DLC 边界与回归

## 7. README 必写内容

- 已移植内容。
- 「与联机版的差异」表：联机版做法 → 单机版做法，以及原因。
- 兼容性：与哪些模组共存、哪些不能同时启用。
- 开发说明：`_ai_work/` 里的工具和自动测试怎么跑。
- 建议实机回归清单，以及已经实测的范围和**未覆盖**的范围。
