# 04 音效移植

## 1. 先盘点

1. 在联机版的 prefab、SG、组件、UI 里搜索 `PlaySound`、`KillSound`、`RemapSoundEvent`、`soundsname`、`talker_path_override`，包括字符串拼接出来的路径。
2. 分清：单机已有的声音、缺失的声音、硬编码的语音路径、只在测试函数里出现的事件。
3. 建事件清单：源工程/组/事件 → 目标事件路径 → 调用文件 → 一次性还是循环 → 停止方式 → 验证状态。
4. 所有路径集中写在 `main/sounds.lua` 的常量表里，调用处统一读表。

## 2. 两种做法

### 做法 A：直接复用官方 FEV，改工程名（推荐，温蒂 2026-10-28）

单机和联机版的 FEV 都是 FMOD Designer 4.44 的 `RIFF 'FEV ' FMT 0x450000`，波形库都是 FSB5。所以不重建工程，直接复制 Klei 的 FEV，只改名字：

1. 改工程名（PROP、LGCY 块）和全部波形库名（LGCY 块），重写 PROJ 列表的 RIFF 填充字节，并同步 `OBCT` 预分配计数（id 19 = 工程名字节数，id 20 = 全部库名字节数）。**不改计数会在加载时报 FMOD 错误 43。** 不改名时输出应与原文件逐字节一致，可以用来自检工具。
2. 精简 FSB：用联机版 `bin64` 的 FMOD 运行库逐个播放目标事件，记录实际用到的样本（PCM 长度、声道、默认频率），匹配到 FSB 样本头；没用到的样本替换为同编码的最短样本，**样本索引不变**。
3. 事件路径和联机版一致，只换工程名：`wendy_dst/characters/wendy/summon`、`wendy_meta5/wendy/basket_open`、`wendy_skilltree/ui/skill_mastered`。

现成工具和完整步骤：`DS_GAME_DIR\mods\wendy\_ai_work\audio\`（`README.md`、`tools/fev_rename.py`、`fmod_probe.py`、`match_samples.py`、`build_banks.py`、`ds32/DsFmodTest.exe` 单机 32 位运行库加载测试）。

这种做法完整保留多轨、层、包络、DSP、循环设置，不会失真。

### 做法 B：重建 FDP 工程再编译（沃托克斯、薇诺娜、机器人）

用 DST Mod Tool 从 FEV/FSB 反推 FDP，再用 FMOD Designer 4.44 编译。适合要自己剪辑、合并多个来源事件的情况。

- 反推出的 FDP 不等于官方原始工程，要对照事件层级和参数。
- **不要把同时播放的多轨声部合并成一个随机样本池**：沃托克斯旧包因此丢了声部、密集触发时互相抢占。
- 4.44 简单一次性事件用 `startmode=0 / loopmode=1 / loopcount2=-1 / oneshot=Yes`；旧组合 `loopmode=0 / loopcount2=0` 会编成非一次性。不要把这组参数套到循环事件上。
- 编码用 VORBIS（FSB mode `0xf`）。
- 样本扩展名可能和真实格式不符（`.wav` 实为 `OggS`），需要先解码为真实 PCM。

工具与命令：`DS_PORT_KIT_DIR\references\audio-porting.md`、`fmod-build.md`、`dst-mod-tool-klei-export\SKILL.md`；FMOD Designer 在 `FMOD_DESIGNER_DIR`。

## 3. 命名与注册

- **事件路径 = 工程内部名/组/事件**，与 `.fev` 文件名无关。只改文件名不能改路径。
- 工程名必须唯一，加角色前缀：`walter_meta5`、`wendy_dst`、`wx78_circ`。和单机自带的 `dontstarve` 或其他移植模组同名会冲突。
- FEV 与它引用的**全部** FSB 成套放进 `sound/`，配对以 FEV 里记录的库名为准，不要按文件名猜（例：`wandatock.fev` 对应 `wandatocksfx.fsb`）。
- 只在 `modmain` 的 `Assets` 里注册一次，不要在 prefab 里重复注册。
- `sound/` 文件缺失时可以退回单机自带声音，不注册缺失的包（温蒂的做法）。

## 4. Lua 接入

- **硬编码路径用 `TheSim:RemapSoundEvent(旧, 新)`**：单机 SG 有些分支（受伤、死亡、溺水、毒气面具）不读 `talker_path_override`，直接拼角色名路径，必须重映射。SW/Hamlet 会额外请求 `sinking_death`、`gasmask_hurt`、`gasmask_talk`。
- 设置 `inst.talker_path_override = "<工程>/characters/"` 让说话走模组 bank。
- **循环声必须命名播放，并在所有退出路径 `KillSound`**：技能停用、主人死亡、实体休眠、实体移除、读档。循环声可能挂在骑手的 SoundEmitter 上，要记住是哪个 emitter 在播，移除时一起清理。
- 骑乘时坐骑相关的声音（冲刺、技能音效）改由骑手发声。
- 正确的一次性事件会自然结束。不要用定时 `KillSound` 掩盖工程参数错误。
- 技能树 UI 音效的类别是 `set_sfx/HUD`，暂停时仍可听见；前端音量约 0.75。

## 5. 验证

- **静态核对事件路径**：解析 FEV 得到完整事件路径列表（沃尔特 `_ai_work/fev.py`，可从该模组 git 历史取回），把 `main/sounds.lua` 里的全部路径和代码里的字面量路径逐条比对本模组 bank 和单机本体 + 三个 DLC 的 bank 列表，要求 0 条缺失。
- 用 FMOD 运行库无声播放（做法 A 的 probe 工具）确认事件可加载、一次性事件自然结束、循环事件持续。
- 实机：日志里没有与模组 FEV 名相关的 `FMOD Error`；人耳试听音量、3D 衰减、与动作时间轴对齐。运行库静音测试通过不等于已完成实机试听，报告里要分开写。
