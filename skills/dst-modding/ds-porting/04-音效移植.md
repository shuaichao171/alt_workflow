# 04 音效移植

## 1. 先盘点

1. 在联机版的 prefab、SG、组件、UI 里搜索 `PlaySound`、`KillSound`、`RemapSoundEvent`、`soundsname`、`talker_path_override`，包括字符串拼接出来的路径。
2. 分清：单机已有的声音、缺失的声音、硬编码的语音路径、只在测试函数里出现的事件。
3. 建事件清单：源工程/组/事件 → 目标事件路径 → 调用文件 → 一次性还是循环 → 停止方式 → 验证状态。
4. 所有路径集中写在 `main/sounds.lua` 的常量表里，调用处统一读表。

## 2. 两种做法

### 做法 A：直接复用官方 FEV，改工程名（推荐，温蒂 2026-10-28）

单机和联机版的 FEV 都是 FMOD Designer 4.44 的 `RIFF 'FEV ' FMT 0x450000`，波形库都是 FSB5。所以不重建工程，直接复制 Klei 的 FEV，只改名字：

1. 改工程名（PROP、LGCY 块）和全部波形库名（LGCY 块），重写 PROJ 列表的 RIFF 填充字节，并同步 `OBCT` 预分配计数（id 19 = 工程名字节数，id 20 = 全部库名字节数）。**不改计数会在加载时报 FMOD 错误 43。** 不改名时输出应与原文件逐字节一致，可以用来自检工具。
2. 精简 FSB：用联机版 `bin64` 的 FMOD 运行库逐个播放目标事件，记录实际用到的样本（PCM 长度、声道、默认频率），匹配到 FSB 样本头；没用到的样本替换为同编码的最短样本，**样本索引不变**。
3. 事件路径和联机版一致，只换工程名：`wendy_dst/characters/wendy/summon`、`wendy_meta5/wendy/basket_open`、`wendy_skilltree/ui/skill_mastered`。

现成工具（温蒂的 `_ai_work/audio/` 已随发布清理）：`DS_GAME_DIR\mods\winona\_ai_work\audio\`（薇诺娜，2026-10-29）：
- `fev4.py`：纯 Python 解析 FEV（LGCY+STRR），得到 事件 → sounddef → (bank, 样本索引)；联机版 `dontstarve.fev`（2905 事件）和 `meta4.fev` 都能完整对齐解析，不需要运行库探测样本。
- `build_banks.py`：改工程名和全部 bank 名（不改名时逐字节一致自检），按 `KEEP_*` 事件清单精简 FSB（PCM 样本换 1 帧静音，Vorbis 样本换库内最短样本，索引不变）。
- `mp3pack.py`：把 PCM16 样本重编码为 FSB5 MPEG（mode 11，单机自带库也用这种编码）。要点：**每个 MP3 帧补齐到 4 字节**（44.1kHz 帧长 364/365 交替，不补会让 FMOD 解码错位）；读出 Info/LAME 标签帧里的编码延迟后丢弃该帧；LOOP 块从 1105 采样（576+529）开始，事件级循环无缝。官方 meta4 93MB → 3MB。
- `fmod_probe.py`：用联机版 64 位 `fmod_event64.dll` 静音播放每个事件；`fsb_decode_check.py`：经 FMOD 解码后按 10ms 响度包络和能量比对原样本（MP3 不能用波形 SNR 判断）。

这种做法完整保留多轨、层、包络、DSP、循环设置，不会失真。

### 做法 B：重建 FDP 工程再编译（沃托克斯、薇诺娜、机器人）

用 DST Mod Tool 从 FEV/FSB 反推 FDP，再用 FMOD Designer 4.44 编译。适合要自己剪辑、合并多个来源事件的情况。

- 反推出的 FDP 不等于官方原始工程，要对照事件层级和参数。
- **不要把同时播放的多轨声部合并成一个随机样本池**：沃托克斯旧包因此丢了声部、密集触发时互相抢占。
- 4.44 简单一次性事件用 `startmode=0 / loopmode=1 / loopcount2=-1 / oneshot=Yes`；旧组合 `loopmode=0 / loopcount2=0` 会编成非一次性。不要把这组参数套到循环事件上。
- 编码用 VORBIS（FSB mode `0xf`）。
- 样本扩展名可能和真实格式不符（`.wav` 实为 `OggS`），需要先解码为真实 PCM。

工具与命令：`DS_PORT_KIT_DIR\references\audio-porting.md`、`fmod-build.md`、`dst-mod-tool-klei-export\SKILL.md`；FMOD Designer 在 `FMOD_DESIGNER_DIR`。

## 3. 命名与注册

- **事件路径 = 工程内部名/组/事件**，与 `.fev` 文件名无关。只改文件名不能改路径。
- 工程名必须唯一，加角色前缀：`walter_meta5`、`wendy_dst`、`wx78_circ`。和单机自带的 `dontstarve` 或其他移植模组同名会冲突。
- **同名冲突是实测的硬错误**（威尔逊 2026-10-31，实测）：两个模组各自注册内部工程名相同的 FEV（wolfgang、woodie、早期 wilson 都用 `wilson_rework`），第二次 `EventSystem::Load` 返回 **FMOD error 92（already loaded）**，磁盘上文件逐字节相同也没用。确实要共用一个包时只能由一个模组负责加载；做不到就按做法 A 改工程名（同时改 bank 名与 `OBCT`，只改名字时输出应与原文件逐字节一致，可先自检）。
- 只做“改名重建”（做法 A）时可以不精简样本：官方 FSB 原样随包（威尔逊的 `wilson_skilltree.fsb` 245 KB）不会失真，也没有重编码风险；需要减体积时再走 §2 做法 A 第 2 步的精简。
- **one-shot 标记不等于会自己结束**（机器人 2026-10-31，实测：单机 4.44.64 运行库）：DST 的 `WX_rework/screech/loop` 工程属性是 one-shot，静音探针播放 15 秒仍在响，DST 自己也是命名句柄 + `KillSound` 结束。这类事件按循环声处理，探针用“持续 N 秒后显式停止”验收（wx78 `tests/audio_runtime_probe.cs` 的 `sustain` 模式），不要用“自然结束”判定。
- **Hand-rebuilt bank 必须逐事件验收循环/一次性语义**（沃姆伍德 2026-10-31）：重编 `grotto` 银行把本应一次性的 `light_bug/hit`、`death` 做成了死循环，无名 `PlaySound` 每受击叠一个永不停的循环；事件属性块字节补丁改不动时，从官方 FEV 改名重建+裁剪即可对齐（`compare_banks.py` 用 NOSOUND 运行时逐事件对比模组 vs DST 原版，是最可靠的判定器）。
- 多 bank 官方工程裁剪时**只发被引用 bank 的 FSB**（winona_dst 先例）：沃姆伍德的 `wormwood_grotto` 改名自 `grotto.fev`（banks `grotto_sfx`+`grotto_amb`），21 个事件全部只引用 sfx 库，就只随包 `wormwood_grotto_sfx.fsb`（裁剪到 26 条波形、索引不动），amb 不发也能加载（FMOD 懒开未引用 bank）。
- 事件路径验证的**游戏侧索引要含每个 DLC 自己的 sound 目录**（`data/sound`、`DLC0001/sound`、`DLC0002/sound`、`DLC0003/sound`）：哈姆雷特的 `dontstarve_DLC003/characters/wormwood/fertalize_LP` 等事件在 `DLC0003/sound/dontstarve_DLC003.fev`（710 事件），只索引 `data/sound` 会误报缺失。
- FEV 与它引用的**全部** FSB 成套放进 `sound/`，配对以 FEV 里记录的库名为准，不要按文件名猜（例：`wandatock.fev` 对应 `wandatocksfx.fsb`）。
- 只在 `modmain` 的 `Assets` 里注册一次，不要在 prefab 里重复注册。
- `sound/` 文件缺失时可以退回单机自带声音，不注册缺失的包（温蒂的做法）。

## 4. Lua 接入

- **硬编码路径用 `TheSim:RemapSoundEvent(旧, 新)`**：单机 SG 有些分支（受伤、死亡、溺水、毒气面具）不读 `talker_path_override`，直接拼角色名路径，必须重映射。SW/Hamlet 会额外请求 `sinking_death`、`gasmask_hurt`、`gasmask_talk`。海难 `SGwilson` 的 `death_boat` 还会硬编码 `dontstarve_DLC002/characters/vanilla/<角色>_drown_voice`，哈姆雷特打哈欠请求 `<talker_path_override><角色>/yawn`；单机没有对应事件时会静音，要一并重映射（薇格弗德 2026-11-07，源码）。沃特 v0.2.0 就漏了 `_drown_voice`：`verify.py` 只检查 `talker_path_override` 拼出来的路径时发现不了，要把这类写死路径单独列进检查表（沃特 2026-11-07，源码）。
- 设置 `inst.talker_path_override = "<工程>/characters/"` 让说话走模组 bank。
- **循环声必须命名播放，并在所有退出路径 `KillSound`**：技能停用、主人死亡、实体休眠、实体移除、读档。循环声可能挂在骑手的 SoundEmitter 上，要记住是哪个 emitter 在播，移除时一起清理。
- 骑乘时坐骑相关的声音（冲刺、技能音效）改由骑手发声。
- **核对脚本要覆盖常量表**：除了字面 `PlaySound`，把 `sounds.lua` 里 `前缀 .. "事件"` 形式的常量也展开后查 bank，DST 引擎层路径（如 `dontstarve/common/twirl`）在单机根本不存在（薇格弗德 2026-11-07，源码）。
- **移植 DST 的音乐主题（dynamicmusic busy theme）**：单机 base/RoG/SW/Hamlet 四份 `dynamicmusic` 不同（哈姆雷特缓存 `currentbusy`），不要抢 `busy` 槽。在玩家 SoundEmitter 上开独立命名槽，用事件自带的 `intensity` 参数淡入淡出（DST 音乐事件与单机 busy 音乐同为 0~1，置 0 后约 2 秒淡完再 `KillSound`）；播放期间把 `busy`（哈姆雷特还有 `tone`）intensity 压 0，并在该玩家的组件实例上包装 `OnStartBusy`（抑制）与 `OnStartDanger`（让位给战斗音乐）——实例字段遮蔽类方法，四个版本通用。音乐事件的混音类别 `set_music/soundtrack` 单机也有，音量滑块自动生效（薇格弗德 2026-11-07，源码 + FMOD 探针 + 离线模拟，未实机）。
- 正确的一次性事件会自然结束。不要用定时 `KillSound` 掩盖工程参数错误。
- **one-shot 属性不可信，按实测分类**：rifts5 里 one-shot 属性为 0 的 `electro_ball_explode`、`generic_metal/ratchet`、`wagdrone_stationary/beep_hurt`、`wagdrone_flying/walk_pst` 在单机 4.44.64 运行库里都不自然结束，不命名播放会一直占通道；反过来 `WX_rework/screech/loop`、`dizzy/loop` 标着 one-shot 却是持续音。凡要不命名播放的事件，先用探针的 `ends` 模式确认自然结束；持续音只能命名播放并在所有退出路径 `KillSound`（机器人 2026-11-06，实测运行库）。
- 带参数的循环（如 `dizzy/loop` 的 `dizziness`）在命名播放后用 `SoundEmitter:SetParameter(句柄, 参数, 值)` 驱动，值的映射照抄 DST（机器人 2026-11-06，源码）。
- 技能树 UI 音效的类别是 `set_sfx/HUD`，暂停时仍可听见；前端音量约 0.75。

## 5. 验证

- **静态核对事件路径**：解析 FEV 得到完整事件路径列表（沃尔特 `_ai_work/fev.py`，可从该模组 git 历史取回），把 `main/sounds.lua` 里的全部路径和代码里的字面量路径逐条比对本模组 bank 和单机本体 + 三个 DLC 的 bank 列表，要求 0 条缺失。
- 用 FMOD 运行库无声播放（做法 A 的 probe 工具）确认事件可加载、一次性事件自然结束、循环事件持续。WX-78 的 `tests/audio_runtime_probe.cs` 有 `play` / `sustain`（持有后显式停止）/ `ends`（不论属性都要求自然结束）/ `concurrent` 四种模式，可直接复用。
- 实机：日志里没有与模组 FEV 名相关的 `FMOD Error`；人耳试听音量、3D 衰减、与动作时间轴对齐。运行库静音测试通过不等于已完成实机试听，报告里要分开写。
