# 00 注意事项

本文件只记录必须遵守的原则，不描述先做什么、后做什么。实际执行顺序见 README 的流程总览和 01—04；模板与记录格式见 06。

## 范围与版本

- 先冻结个体、用途、显示尺寸、bank、build、entity、动作名、方向、FPS、循环方式、命中事件和装备/皮肤契约。
- 三视图、部件 PNG、骨骼工程、SCML、编译包和验收媒体必须来自同一修订。源工程修改后必须重新导出、编译、验包并更新哈希。
- G6 是源工程与官方编译包交付；G7 是游戏和联机实测。没有游戏测试不能写成 G7 通过。
- 预览网页、GIF、MP4、PNG 帧序列、JSON 或普通工程 ZIP 都不能替代官方 Mod Tools 编译的 `anim/*.zip`。

## 30 FPS 硬性要求

- 自 2026-09-18 起，OpenSpine 母版、关键帧时间基准、原生采样、预览播放和最终编译动画统一为 **30 FPS**。不得因工具默认值改交 24、25、40 或 60 FPS；帧率要求必须进入 P0 与 G6 验收。
- “30 帧”指每秒 30 帧，不是每个动作总共 30 张。每段分别记录循环周期/单次时长、采样帧数、末姿时间和保持段；F0 为零时刻，`t = F / 30` 秒，例如 F12 = 400 ms。
- SCML 整数毫秒由绝对帧号换算为 `round(F × 1000 / 30)`，明确记录量化规则和误差；不累计固定 33 ms，也不把 33 ms 称作精确 30 FPS。细则见 04 第 5 节。
- 最终从 `anim.bin` 逐动作读取实际 FPS、帧数和时长，并核对命中/换图等事件。只改预览播放速度、文件标签或二进制 FPS 字段不能满足要求；必须使用经过 P0 验证的官方编译链重建。
- 旧资产的旧采样、导出和编译记录照实保留，不回写成新规范已通过；采用旧资产须按本要求重新验证。

## 素材与骨骼

- 已确认的三视图是身份和风格基准，不擅自换脸、换比例或混用个体。
- 图片名称不能代替语义。必须根据实际 PNG、附件、父子链和原生渲染确认部件职责。
- 关节链（如肩—肘—腕、髋—膝—踝）必须来自一条连续的父子关系；只移动末端贴图、让末端部件脱离上一级骨段或用临时标记代替真实骨骼都不算完成。
- 换图前先量透明像素的可见轮廓和关节锚点，再叠加动作强调；不能把图片尺寸、骨骼缩放和继承缩放重复放大。
- 调整体型先在同一原版动作、朝向、原点和渲染比例下测量可见轮廓，并确认修改的是贴图还是运行时显示比例。要求改贴图时，直接修改可重建 PNG 源文件及必要的画布/pivot，不能用角色代码缩放替代。原版骨架的关节间距不会随 PNG 自动改变；应围绕关节处理部件、同步头部与表情的相对挂点，并单独检查戴帽版本的头发和耳朵遮挡。普通与专属动作都须重新组合实际人物 Build 验证，避免在 PNG、Build 和动作状态中重复补偿。
- 保留模板要求的骨骼、slot、skin、装备通道和可选时间线。编译临时投影不能删源 SCML 的通道。

## 游戏贴图替换与原点

- **动画包内的 Build 不等于游戏实际使用的 Build。** 制作前确认角色基础 Build、皮肤、装备和临时覆盖的实际来源；验收须组合安装包的 `anim.bin` 与运行时真正选中的 `build.bin`/TEX，不能只看工程预览或包内自带 Build。操作步骤见 04 第 5.3 节。
- 同名 symbol、相同 PNG 尺寸甚至相同像素，都不能证明替换后位置一致。逐 symbol/frame 核对真实帧号、持续范围、SCML file/object pivot、Build 中心偏移、完整矩阵和层级；不能按数组下标或截断到最后一帧来掩盖缺图。
- 居中原点的动作直接配用非居中原点的角色 Build，会使头、脸、躯干和四肢分别错位。保持基础 Build 时，应在源文件/编译中间数据中完成配准和原点补偿，再由官方工具编译；补偿方向以官方顶点规则和独立渲染验证，不以适配器自身的零误差自检为依据。
- 使用专用 Build 或 `AddOverrideBuild` 的动作，必须把覆盖列入接入契约：播放前生效，进入/循环/退出及主客机分支完整，结束和打断后只清理本动作拥有的覆盖。装备或皮肤的单 symbol 覆盖需要另外核对，不能把增加一个 Build 当作通用兼容修复。
- 需要显示人物自身外观及装备时，可使用仅含动画的资源包，但必须补偿人物 Build 原点，并逐帧输出原版装备图层。`HEAD`、`HEAD_HAT`、`HAT`、`ARM_normal`、`ARM_carry` 等名称与实际装备回调保持一致；帽子、持物臂和 `swap_object` 需要活动 mainline 引用及正确挂点，仅保留隐藏备用轨道或取消专用覆盖都不够。显隐、皮肤和 symbol 覆盖由原装备代码管理，动作退出不能恢复成过期的换装状态。
- 装备验收须查实际 Prefab：普通帽、露顶帽、全盔、武器、提灯可能使用不同图层、帧持续范围和跟随特效。空 symbol 加独立特效的装备不能用角色贴图回退伪造“显示正常”；离线渲染未包含的特效和引擎行为应单列待游戏验证。
- 对照至少覆盖默认外观、实际贴图替换、首末与关键姿势、打断后恢复；注明所用 Build 和源/安装包哈希。编译资源重建和 Lua 生命周期测试不代表游戏内视觉或联机实测通过。

## 动作与方向

- 攻击类动作先明确预备、蓄力、发力、命中、过冲和回收；轻重区别由时间、路径、身体跟进和恢复共同表达，不能只靠放大部件。
- 连续攻击若采用同一站姿，须明确人物解剖学哪只脚在前，并检查左右交替全程及互接时的腿和脚。脚目标不动不等于腿不抖：移动的髋部父链、IK 伸缩或镜像继承仍可改变腿的矩阵。固定站姿应在可编辑骨骼源中稳定髋部参考与脚目标，保持上身动作，并核对真实腿/脚附件、绘制顺序和换 Build 后的顶点；不能按误名的 timeline 判断身体部位。
- `left`、`right`、`down`、`up` 的镜像和人物解剖左右必须按项目契约固定，不能把屏幕左右当成人物左右。
- 每个方向都单独检查手心/手背、前后遮挡、远侧肢体和层级。换 attachment 时同时检查贴图语义，不能只检查角度和位置。
- 局部返工必须记录动画、方向、timeline、时间点、旧值、新值和允许影响范围，并回归未修改方向、对侧肢体、首末姿势和事件。

## 验证、接入与发布

- 原生渲染、独立 SCML 重建和编译包/游戏画面是三层验证，任何一层都不能用另一层的结果冒充。
- 攻击命中由运行时代码和服务器状态决定；动画事件、命中帧和状态图必须相互对照。
- 资源接入不得擅自替换 build、装备层或用户已有资源；需要独立攻击层时记录其实际发出的 symbol/layer。
- manifest 必须记录相对路径、工具版本、依赖、命令、退出码和 SHA-256；清单中的哈希必须与最终文件一致。
- OpenSpine 使用公开仓库 [l1790780473/openspine](https://gitee.com/l1790780473/openspine) 作为获取入口；发布包排除 `.git/`、个人配置、绝对路径、用户名、缓存、`__pycache__/`、临时导出和浏览器 profile。工具路径只通过 `DST_GAME_HOME`、`OPENSPINE_HOME`、`DST_MOD_TOOLS_HOME`、`DST_SCML_ANALYZER` 或未提交本地配置注入。
- 流程文档只描述通用方法；本仓库不分发具体项目的路径、截图和脚本，因此不能把文档里的说明写成可直接运行的入口。
